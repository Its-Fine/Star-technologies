# Передача сайта и запуск

Сайт создан для согласования и не опубликован. Любой deploy, включая приватный адрес Sites, выполняется только после отдельного подтверждения владельца.

## Что нужно подтвердить владельцу

- Домен, рабочая почта, телефон и юридические реквизиты.
- Реальные условия предложения и поставок, ассортимент, документы и контакты.
- Выбранный хостинг и требования к месту хранения данных; подготовить итоговую политику обработки данных вместо чернового описания.
- CRM и канал уведомления о новых заявках. Пока CRM не настроена, менеджер видит заявки в `/admin`; сайт не отправляет письма или сообщения автоматически.

## Хостинг

Подготовленная сборка использует Cloudflare Workers + D1 + R2. Вариант Sites имеет готовую конфигурацию `.openai/hosting.json` с привязками `DB` и `BUCKET`. После подтверждения можно развернуть сохранённую версию приватно для проверки. Публичный доступ включается отдельно по инструкции владельца.

Для собственного хостинга сохранить frontend можно; серверная часть требует среды с совместимыми D1/R2 API либо адаптации хранилища под выбранные БД и S3. Обычный статический хостинг не принимает заявки через этот backend. Автономный HTML — версия для просмотра, не серверная установка.

Для рабочего окружения задать `ADMIN_TOKEN` и `RATE_LIMIT_SALT`; подключить D1/R2 и применить миграции. CRM и курс настраиваются по необходимости. Не переносить `.wrangler`, реальные данные и секреты в архив исходников.

## Домен и SEO

1. Выбрать и зарегистрировать домен; в этой работе домен не регистрировался.
2. Подключить его через выбранный хостинг, внести выданные провайдером DNS-записи и дождаться сертификата TLS.
3. Обновить `config/site.ts`: `origin`, контакты; использовать единственный канонический адрес и настроить редирект с альтернативного хоста.
4. Подтвердить страницы, реквизиты и документ обработки данных.
5. Для публичного запуска установить `published: true`, пересобрать и опубликовать. До этого `robots.txt` и meta robots закрывают индексацию.
6. Проверить `/robots.txt`, `/sitemap.xml`, canonical и Open Graph на фактическом домене.

## Проверка в реальном браузере перед запуском

Открыть главную, каталог и заявку при ширинах 320, 390, 768, 1024 и 1440 px. Проверить меню, поиск, пустой результат, переход категории, карточку, ₽/$, клавиатуру и закрытие формы Esc. Отправить одну тестовую заявку с файлом, найти её в `/admin`, скачать вложение и проверить получение в настроенной CRM. Затем удалить тестовые данные в рабочей базе согласно принятому процессу.

Проверка начальных сигнатур файлов не является антивирусным сканированием. Файлы выдаются только как скачивания и только с ключом администратора; для рабочего процесса можно подключить отдельную проверку вложений по правилам компании.
