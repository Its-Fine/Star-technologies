# Подключение CRM

Конкретная CRM ещё не выбрана, её доступы не запрашивались и данные третьим лицам не отправлялись. Подготовлен универсальный HTTPS webhook. Он не утверждает совместимость с нативным API Битрикс24 или amoCRM без адаптера.

1. Подготовьте серверный адаптер, который принимает нижеописанный JSON и создаёт лид в выбранной CRM.
2. Задайте `CRM_WEBHOOK_URL` и при необходимости `CRM_WEBHOOK_TOKEN` в настройках хостинга.
3. Ответ адаптера 2xx означает принятие. Он должен обрабатывать повторный `Idempotency-Key` без создания дубля.
4. После сохранения заявки сайт делает POST с тайм-аутом 4 секунды. Сбой отмечается `error`; исходная заявка остаётся в D1. Автоматический планировщик повторов не включён. В `/admin` есть ручной повтор.

Заголовки: `Content-Type: application/json`, `Idempotency-Key: <номер заявки>`, необязательный `Authorization: Bearer <CRM_WEBHOOK_TOKEN>`.

```json
{
  "source": "star-technologies",
  "lead": {
    "id": "<номер заявки>",
    "name": "<имя>",
    "company": "<компания>",
    "email": "<почта>",
    "phone": "<телефон>",
    "location": "<город и страна>",
    "message": "<задача>",
    "product": "<выбранная модель>",
    "currency": "RUB",
    "created_at": 0,
    "consent_version": "2026-10-11-draft",
    "attachment_name": "<имя файла или null>",
    "attachment_type": "<тип или null>",
    "attachment_size": 0,
    "crm_status": "pending"
  },
  "attachmentDownloadPath": "/api/admin/leads/<номер>/attachment"
}
```

Значения выше — обозначения полей, не реальная заявка. При отсутствии вложения его поля и путь равны `null`. Путь относительный; это не открытая ссылка. Адаптер скачивает файл с сервера отдельно с авторизацией. Не передавайте `ADMIN_TOKEN` посетителю или в публичный URL.

Для просмотра заявок: `GET /api/admin/leads` с Bearer-ключом. Для вложения: `GET /api/admin/leads/:id/attachment`. Для повторной передачи: `POST /api/admin/leads/:id/retry`. Публичного API выдачи заявок или файлов нет.
